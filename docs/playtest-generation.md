# Seeded synthetic movement generation

`pcx_play::generator::generate` emits a strict, version-one `.rpl` scenario from
caller-supplied domains and explicit limits. `playgen` exposes the movement-v1
recipe as a command. This supplies reproducible synthetic inputs for Tier C;
it does not supply native traces or native-gameplay behavior.

The profile varies unit owners and raw fixed-point positions, action ticks and
move/select/stop/nop/RNG actions supported by the existing simulation harness.
Unit counts, tick counts, action counts, owner choices, coordinate ranges and
action choices come from `MovementSpec`. The library retains the supplied
scenario/map identity, asset mode and fix rows. No game asset is read or copied.

Generation starts a separate `pcx_sim::Rng` with `RunConfig.seed`. Execution
starts its own stream at the same seed. Selection uses modulo arithmetic over
the requested domains, including the entire signed i32 coordinate domain. This
is a reproducible project convention with modulo bias, not native `FRand` or
an unbiased statistical distribution. Declaration order is retained for
same-tick actions. Generator names and profile identifiers are synthetic.

## Limits and refusals

Every call supplies `Limits`: unit/action/tick/fix-row counts, the single-run
work estimate and output bytes. Work is `ticks * (units + 1) + actions`, matching
the existing `playrun` estimate. Validation checks canonical names, unique
owners/action choices/fix IDs, nonempty required domains, coordinate ordering,
the simulation's u32 unit-ID source and platform tick-vector layout before
generating text. Zero units/actions are accepted; zero ticks are refused because
RPL requires an assertion at a real tick.

Output growth checks the byte ceiling, platform array layout and fallible
reservation before each append. Errors return no generated source. The CLI
prints source only after successful generation, so a refusal does not print a
partial RPL. Its unit/action ceilings are resource policy (1,024/16,384), not
native limits. These limits do not bound all runner/oracle allocations, validation
time or wall-clock work. In particular, fix-ID duplicate checking is quadratic
in the explicitly capped fix-row count.

The generated assertion checks the final unit count. It deliberately does not
derive expected positions from a candidate execution and call that a native
baseline. Run additional authored expectations or compare independent oracles
when testing behavior.

## Command and corpus

```text
playgen SEED TICKS UNITS ACTIONS MIN_X MAX_X MIN_Y MAX_Y MAX_WORK MAX_BYTES OWNER [OWNER ...]
```

The CLI uses vanilla mode, no fix rows and all five supported action choices.
The library accepts other explicit configurations. Coordinates are raw `Fx`
integers; no native world-unit conversion is inferred.

The synthetic corpus at `tests/play/synthetic/generated-movement/` uses seeds
zero, one and u64::MAX. Each file is regenerated by:

```sh
cargo run --locked -p pcx-play --bin playgen -- \
  SEED 12 8 24 -2147483648 2147483647 -100000 100000 132 16384 0 1
```

Then execute the generated RPL through the existing runner:

```sh
cargo run --locked -p pcx-play --bin playrun -- \
  tests/play/synthetic/generated-movement/seed-0.rpl /tmp/seed-0.trace --runs 100 --max-work 13200
```

`generator` integration tests regenerate all three files byte-for-byte and run
each independently 100 times. They also check strict ingestion, identity, every
supported action, signed-coordinate boundaries, exact budgets, typed invalid
domains, real CLI output/refusals and fresh generated pairs through the existing
seed minimizer. The profile is pinned by corpus bytes; an algorithm/domain change
requires deliberate recipe versioning instead of silently refreshing expectations.

Terrain generation, combat/ability/unit-type compositions, native RNG and event
ordering, original-runtime baselines, automatic divergence filing and the full
Tier C zero-unexplained-divergence gate remain open. Equal synthetic repeats
prove harness reproducibility, not Warcraft III fidelity.

Verification also includes native library/binary builds, scoped strict Clippy,
linked `wasm32-unknown-unknown` library/binaries and four actual 32-bit WASM cases:
oversized tick layout, exhausted unit-ID capacity, the complete signed-coordinate
domain and an output-byte refusal. These checks establish platform safety for
the tested boundaries, not browser or native-game execution.
