# Regular music volume

This bounded slice adds the normal unsigned volume domain to the existing
regular map-music consumer. It does not admit regular PlayMusic/Ex, StopMusic,
ResumeMusic, regular seek or fades. Those calls keep their existing explicit
refusals. The accepted thematic request, restart, seek and retirement path stays
separate.

The selected native client is Warcraft III.exe 1.29.2.9231, SHA-256
`3f2ed0120d80578bf07e4423296dade1adfb959d59a2d20a7584224559570eed`.
The selected local backend reports FileVersion 3.0.0.0, SHA-256
`cc142b9d8b5223e2720c6440cb7a124c0a80d2fb04ecf59ad7331dfd6e3cb51f`.
Neither image nor a generated copy of its data is stored in the repository.
Local source-window hashes and disassembly receipts are retained under
`/tmp/pc3-lane07-regular-music/`.

## Native-code joins

SetMusicVolume's wrapper reaches `0x5da420`. That routine saves the unsigned
minimum of the argument and its image operand for future regular starts. If a
regular handle exists, it passes the original argument to `0x7a0310`. The
ordinary domain admitted here makes those two values equal. Negative and larger
arguments remain explicitly unqualified; they are not claimed invalid in the
original client. Thematic state is held separately and is not this setter's
recipient. The initial saved target is read from its data initializer.

Regular stream creation at `0x5d8d40` and the user-music preference consumer at
`0x5da5a0` both select the same channel. Preference index 28 resolves through
the two-level switch at `0x42ab70` to `0x42ae6c`, which converts the stored
unsigned percentage using an image divisor. `0x5da5a0` multiplies that user gain
by the current music group base. `0x79fa30` clamps this product to the selected
channel unity, then stores the live channel gain. `0x7c9970` multiplies the raw
regular level by that channel gain before integer conversion and table lookup.
Applying user gain after the new table would therefore change the result.

The normal non-spatial stream branch at `0x7c9b22` clamps its index and uses the
table generated by `0x7c6320`. Its offset, bias, peak and entry count are read
from the selected image. The builder converts packed double log10 results to
binary32, normalizes in binary32, walks the destination backwards and truncates
each result. The recreation follows those rounding stages and computes the
table locally. The alternate bypass global has no qualified script setter.
This slice covers the ordinary initialized path; an alternate bypass/provider
mode is not implemented.

The stream-volume call at `0x7c9b51` supplies the import slot to the optional
module transport. The transport must derive the owning PE import descriptor,
retain the module's local identity and pin it to the same source generation.
A loose asset resolver or a second engine-image slot is not a substitute for
that relationship. The policy reads the main image, backend bytes and backend
origin independently; the producer validates their publication relationship.

In the selected DLL, the stream-volume wrapper reaches the sample-volume setter
and mixer update at `0x21114510`. The digital-driver constructor reached through
AIL_open_digital_driver and AIL_waveOutOpen initializes its master field at
`0x21113708`. The main image imports the separate XMIDI master setter, but no
digital master setter. The ordinary initialized digital master is the supported
profile. The main driver call at `0x79db57` requests stereo output; the sample
initializer at `0x2111448e` supplies the centered pan. The two pan-table
coefficients and divide shift are checked against the shared level coefficient.

The source mixer has a special full-scale saturation edge. Startup at
`0x211010c0` registers MIXER_merge and MIXER_copy under its mixer service name;
the scalar and MMX copy paths divide accumulated PCM by the same power-of-two
unit. The policy derives that unit and the setter's shift/threshold instead of
assuming raw level divided by the game's maximum. Sample clipping, resampling,
dithering and arbitrary third-party providers are outside this scalar gain
controller.

These are static native-code joins. No new original client or DLL was executed
for this implementation phase. The passive native computed-table comparison
and audible/sample equivalence remain pending. Platform log10 is a recreation
calculation until its generated integer table is compared with that reference.

## Called path and lifecycle

`MapStartupInputs.regular_music_volume_rules` carries an optional result. A
missing or failed backend policy does not prevent unrelated map startup or
accepted thematic playback. Calling SetMusicVolume with that failed policy
reports the retained source error. Successful normal-domain calls update a
regular request with an immutable policy, level and checked revision; rejected
calls preserve that accepted state. A fresh session reads the source initializer.

The app attaches RegularMusicGain only to regular map music. Both a pending
PlaybackSettings and a live AudioSink receive the combined group/user/table
result. The existing menu-volume system runs after campaign music so newly
attached components are consumed in order. A later regular track inherits the
current request. Thematic tracks receive no new regular gain component. Session
replacement retires the old music entities through the existing session witness.

The shipped Human06Interlude source calls SetMusicVolumeBJ before its thematic
track. The selected unchanged Blizzard SetMusicVolumeBJ and PercentToInt bodies
are exercised through the real VM, rather than replaced by a handwritten helper.
This is a called helper gate, not an unchanged chapter-horizon result.

channel, pan scale and mixer unit. They cover partial/truncated sources,
relationship changes and unsupported inputs. Host tests cover real VM dispatch,
thematic separation, missing module errors, rejected-call atomicity, revision
exhaustion and a fresh host. Native equal-sample audio parity, complete integer
volume behavior and the remaining regular music lifecycle remain open.
