# Original Options value initialization

The qualified Legacy executable, SHA-256
`3f2ed0120d80578bf07e4423296dade1adfb959d59a2d20a7584224559570eed`,
VERSIONINFO 1.29.2.9231, contains a complete Options population routine at
`0x531260..0x531ad4`. Its preference reads connect the named descriptor table
to bound controls. This strengthens the earlier name-based correspondence;
it does not establish the release of adjacent FDF archives or a live first-run
configuration. No original client or preference store was executed or modified.

The checked importer reads fallback bytes from the supplied image. The native
getter can instead return a saved value. These are different inputs, and neither
widget initials nor a nearby descriptor alone establish the effective setting.
See [fallback admission and the current audio consumer](original-options-defaults.md).

## Values, labels and remaining behavior

For the seven quality popups, the returned preference word goes unchanged to
`0x884290`. That body stores the word, forwards it to another delegate, and on
its ordinary title path calls `0x883280`. The latter indexes a pointer array
with that zero-based word before tail-jumping to unread `0x87da40`. The return
then reaches popup title helpers; separate property and sentinel branches can
bypass this path. The native FDF-to-array constructor, nested-menu side effects
and tail target remain unread. Preserving authored MenuItem order is the supported
recreation interpretation; the repeated second MenuItem operand is not a unique
setting ID. Label keys still require the selected localization table.

The slider paths convert the getter word through SSE and a sign-indexed
correction table before calling their value delegate. That correction table and
delegate were not inspected; no percentage divisor, speed curve or gamma
function is inferred. Checkbox paths compare the word with zero and call the
bound-control property delegates; their complete checked/enabled semantics are
separate. The game-port path formats the returned word and calls its text
delegate, without establishing accepted input, network binding or edit limits.
Resolution population and selection have their own
[checked boundary](original-display-modes.md).

The source-only popup adapter prototype selects label keys from checked fallback
bytes and actual parsed FDF order. It refuses missing, malformed, negative,
overflowing and out-of-range values and preserves source identity. A regression
also catches malformed MenuItems being silently dropped by the baseline widget
parser, shifting subsequent indexes. The corrected prototype rejects the entire
preview if any item is malformed, including items after the selected entry.
Its 15 strict leaf tests, including nine existing FDF tests, pass. It does not mutate applied
or draft settings, enable controls, or change renderer quality, and has not been
installed in the app. Showing an unconsumed fallback as a current setting would
misrepresent runtime state.

Native music/effects already have real consumers. Remaining settings require
their input, renderer, audio, network or gameplay owner before activation. These
observed joins remove uncertainty about their source keys; they do not supply
those missing behaviors. Internal recreation implementations may differ from
the original, while authored values and observable behavior must be preserved.

## Shared popup validation

The production widget parser now checks every MenuItem in the supported quoted
nonempty-label/finite-numeric-operand profile. It returns a contextual error for
the entire popup instead of dropping a record or returning an unterminated label.
Later malformed records also refuse; valid order and repeated opaque operands
remain unchanged. Empty dynamic menus remain empty. No numeric operand is
reinterpreted as a setting ID, and no new control or default preview is enabled.

The original production parser fails the new regression before the fix. After
the change, all 13 menu-screen tests and the complete app suite pass: four
library tests, 259 app tests with 12 explicit ignores, and 83 integration tests.
The explicit original Options popup-cardinality gate passes separately for the
selected Legacy and compatibility installs. Strict native/WASM Clippy, full
builds and formatting pass. Actual release-WASM checks pass 49 baseline and
103 panel assertions, with zero uploads, unexpected requests or sockets.
These integration checks preserve valid-source behavior; they do not add a new
rendered/native fidelity claim. Evidence is retained in
`.scratch/options-popup-validation-root-20261016/`.

## Texture quality writes distinct preferences

A later complete Options write routine at `0x538440..0x53882f` reads the
bound TextureQualityMenu ordinal and passes it unchanged to the texquality
preference writer. It separately derives miplevel and texcolordepth through
branches and source operands. This is not a general reversed quality-to-mip
formula: the first authored choice has a different miplevel word from the next
two, while the last choice has a different texcolordepth word from the first
two. These relationships follow instruction data flow; no measured output
table has been installed as a production rule.

The complete writer at `0x42ca10..0x42ca59` stores the incoming preference
word in its selected record. No call follows that store; lookup/insertion
side effects and the actual renderer consumer remain unread. This does not
prove that miplevel is an authored BLP index, how the depth word packs alpha
or color, which texture classes are affected, or when a reload occurs. The
current menu decoder retains only the top image level. A sampler-only change
would therefore be inert, and a quality Apply needs a prepared texture
replacement before preferences are saved.

Independent decoder comparisons match 330 reached instructions across those
two bodies. Four checked data-flow tests pass, including changed source
operands changing derived results and unknown delegates refusing. The first
root replay passed those checks but failed report emission because a metadata
file had not been copied; its failure is retained separately from the corrected
successful replay. Evidence is in
`.scratch/options-texture-quality-policy-20261016/` and
`.scratch/options-policy-root-review-20261016/run-2/`.

A subsequent narrowly qualified call-site search found no literal selector
setup in its assumed 16-byte lookback window. That is a bounded negative,
not absence of a texture consumer: dynamic arguments, earlier setup and other
accessors remain possible. No unsupported quality control was enabled.
