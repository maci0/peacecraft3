# Campaign AI unit costs

The selected client image (`3f2ed0120d80578bf07e4423296dade1adfb959d59a2d20a7584224559570eed`) registers `GetUnitGoldCost` and `GetUnitWoodCost` at `0xab5430` and `0xab54c0`. Both inspect the rawcode's first byte, then read the active AI player's state slot through `0x7fb2b0`. The checked `GetPlayerState` path addresses that slot as `(state + 4) << 4`; selected `common.j` (`3c21e998bf80d1e04718bd3f2ee7ef2bf1b83359e5b303a56cf59cd61a2afdcd`) binds `PLAYER_STATE_RESOURCE_HERO_TOKENS` to the matching state. The cost branch compares the signed slot value with its image operand and returns zero for matching uppercase rawcodes at or above that threshold. Otherwise it calls the ordinary unit-cost reader. The matching `SetPlayerState` path writes that slot directly. The implementation checks these operand and source relationships against the retained image before admitting the query.

The ordinary values come from the admitted `UnitBalance.slk` `goldcost` and `lumbercost` fields with typed `UnitMetaData.slk` relationships and map `w3u` overrides. Missing rawcodes return zero; malformed or unsupported present definitions refuse. AI-native declarations are checked against the selected `common.ai` before either program runs. An admitted AI context queries its own existing player and catalog; it creates no replacement world or research store.

Synthetic tests cover the image branch shape, exact integer costs, a map override, independent player tokens, an update after AI sleep, unknown rawcodes, malformed declarations and arguments. The explicit selected-image gate requires `PCX_CAMPAIGN_IMAGE`. The controlled RoC observation covers `hfoo`, `Huth` and token 0→1→0; broader native cost parity and other client images remain unqualified.
